## Analysis

**The service-worker heap check fails the strict 20% target: 24.9% growth over the hour.** Every other check passes.

- **Not a leak.** Almost all of the worker's growth happens in minutes 2–12 (0.83 → 1.01 MB). From minute 12 to minute 60 it grows 1.01 → 1.03 MB, about 2% over 48 minutes. With stock flipping every 200 s, the first restock, preorder, new-listing and push code paths only run between minutes 3 and 12. V8 compiles each function the first time it runs and keeps that compiled code on the heap, which looks like growth against a minute-2 baseline.
- **The real cost is tiny.** The whole service-worker heap is about 1 MB, and the offscreen document about 3 MB, while handling 4,637 checks and 159 alerts for 20 monitors.
- **For future runs**, the script also prints growth measured from minute 10, after every code path has run at least once. The pass/fail rule is unchanged.
- **Dedupe held under load.** Every alert matched exactly one stock transition (159 transitions, 159 alerts), with zero duplicates.
- **The scheduler kept pace.** Each 15-second fetch monitor was checked about 232 times against a theoretical 240 (97%). The gap is the ±10% jitter plus polite-mode spacing. Tab-mode counts are about double their check count because each reload also fetches the page's own sub-requests.
